# Problem
- 1~N 정수를 가지고 곱셈과 덧셈을 번갈아 수행하여 최대의 값을 구하라.
- [link](https://www.acmicpc.net/problem/32404)
# Solution

## Algorithm
- Greedy
## Approach
기본적으로는 조합 최적화 문제다. 어떤 순열에서 최댓값이 발생하는가?
주어진 1~N 중 절반은 무조건 곱해지고, 나머지 절반은 더해진다.

N의 범위가 100이다. 또한 수의 범위가 1~N이므로, 계산 결과에는 단조성이 존재한다.
따라서 DP를 고려할 수 있겠다.

하지만, 곱셈과 덧셈이 번갈아 발생한다는 사실에 주목하면 이야기가 달라진다.
계산 식을 고찰해보자.
먼저 더해진 수는 더 많은 수와 곱해지고,
나중에 곱해질수록 더 많은 수와 곱해진다.
따라서 덧셈은 일찍, 곱셈은 늦게 해야 한다.

그렇다면, 어떤 수는 더하고 어떤 수는 곱해야 하는가?
곱셈이 덧셈보다 기댓값이 높다. 따라서 무조건 곱셈을 우선시 해줘야 마땅하다.

# Implementation

## Code

``` rust
use std::io::{Read, Write, stdin, stdout};

fn main() {
    // fast IO
    let stdout = stdout();
    let mut output = std::io::BufWriter::new(stdout.lock());

    let mut input = String::new();
    stdin().read_to_string(&mut input).unwrap();
    let mut iter = input.split_ascii_whitespace();

    // inpit
    let n = iter.next().unwrap().parse::<usize>().unwrap();
    let mut add_val = n / 2;
    let mut mult_val = add_val + 1;
    for i in 1..=n {
        if i & 1 > 0 {
            write!(&mut output, "{} ", mult_val);
            mult_val += 1;
        } else {
            write!(&mut output, "{} ", add_val);
            add_val -= 1;
        }
    }
}
```

## About Code
앞서 깨달은 heuristic을 단순히 코드로 옮겼다.

해 구성하기 특성 상, 여러 답이 나올 수는 있겠지민, 이 풀이가 정해라 생각된다.
## Time Complexity - O(N)
단순 반복문으로 해를 구성했다. 
## Spatial Complexity - O(N)
write buffer를 사용했으므로, O(N)이다. 만약 하나씩 write했다면 O(1)으로 줄일 수도 있겠다.
