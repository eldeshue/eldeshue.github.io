# Overview
리눅스 커널의 최초 진입점이라 할 수 있는 start_kernel이 호출되기 전, 수행해야 하는 작업에 대해서 다룬다.

> 해당 과정은 하드웨어 디펜던트한 부분으로, arch 디렉터리의 아키텍쳐 별 구현에 따라 다르다. 하여 모든 내용을 세세하게 정리하기 보다는, 반드시 해야만 하는 작업이 무엇인지 정리하고 넘어간다.

# Contents
## 0. boot loader
부트로더의 역할은 **커널의 동작을 위한 최소한의 하드웨어 활성화**이다.

- **cpu, 메모리 및 디스크 활성화** : 커널 코드를 실행하려면 하드웨어의 상태가 맞춰져야 한다.
- 커널 **메모리에 적재**: 커널도 프로그램, 메모리에 올려야 한다.
- **부팅 정보 전달(kernel parameter, UEFI/바이오스 정보, 메모리 영역 등)**: 커널에게 현재 문맥 전달
- 커널의 초기화 루틴 실행: 커널에 올렸으면, 커널 실행을 해줘야 한다. 부트로더는 이를 호출한다.

이후 부트로더는 커널의 최초 진입점 위치로 점프한다.
## 1. 커널 런타임 초기화(상)
부트로더는 커널 이미지의 진입점으로 점프하는데, 그 곳이 바로 커널의 실행은 아니다. 보통 arch 특화된 초기화 코드로, decomperssor 등에 존재하며 주로 asm으로 구현된다.

커널의 c코드 실행을 위한 실행환경 초기화가 수행된다. 주로 cpu와 ram에 대한 작업을 수행한다.

- 인터럽트 비활성화: 인터럽트 핸들러가 없으므로, 비활성화 필요
- cache 활성화: 최초에는 비활성화 되어있으며, kernel의 시작을 가속하기 위해 활성화가 필요하다.
- 전역 메모리(BSS) 및 메모리 맵 초기화: 약식 페이지 테이블 구성, 메모리 0으로 밀어서 플래그 off

## 2. 커널 압축 해제
일반적으로 커널 이미지는 zimage, bzimage 등 **압축된 상태**로 제공된다. 그 이유는 큰 이미지를 디스크에서 메모리로 올리는 IO 속도보다 작은 이미지에 압축 해제하는 것이 더 빠르기 때문이다.

커널 압축이 해제되려면 기존 이미지의 위치와 압축 해제된 커널의 저장 위치 등을 계산해서 배치한다. 

구현은 어떤 압축 이미지를 만들었느냐에 따라 다르다. 필요한 하드웨어가 결정되면, 그에 따라 확인한다.
## 3. 커널 런타임 초기화(하)
커널 이미지 압축을 해제했으면, 이제 메모리에는 실행 가능한 vmlinux가 세팅되었다. 이제 kernel에 필요한 데이터를 전달하고, 커널이 기대하는 모드를 활성화 해야 한다.

- 프로세서 정보 비교 및 확인 : 부트로더에서 전달받은 프로세서 정보로 processor_type 확인
	- arm에서는 proc_info_list라는 정적 자료구조에서 탐색
	- 부트로더에서 받은 값이 리스트에 존재하는지 비교 확인
	- 탐색에 실패하면 부팅 실패, 종료
- 프로세서 초기화: processor_type에 존재하는 여러 루틴으로 cpu를 커널이 기대하는 모드로 setting
- 가상메모리 초기화: 기초적인 페이지테이블을 구성, 가상 메모리 환경을 준비한다.
- mmu 활성화: 가상 메모리 구조를 가속시킬 mmu를 활성화
- start_kernel 실행
# etc
## 커널 로딩 전 가상 메모리 변환 방법
proc_info_list 등의 정적 데이터는 커널 빌드에서 들어간 값으로, 가상 메모리 주소로 되어있다.

하지만 아직 mmu가 동작하지 않아서 물리 메모리로만 접근이 가능한데, proc_info를 어떻게 찾아서 읽을까?

실행 과정에서는 label이라는 **특정 심볼(가상주소)의 위치를 추적하는 위치 카운터(`.`, 물리 주소 값)를 유지***한다. 따라서 이 둘의 차이를 offset으로 하여 읽으면 쉽게 변환이 가능하다.

# Summary
해당 부분은 하드웨어 초기화가 주를 이루기에 arch 특화 구현이 너무 많다. 따라서 반드시 해야 할 내용을 위주로 정리하면 다음과 같다.

리눅스 커널은 start_kernel 실행 전, 다음의 조건이 선결되어야 한다.

- 실행 가능한 커널 이미지가 메모리에 위치
	- 압축 커널이면 압축 해제
- CPU가 커널이 기대하는 모드에 들어와 있다.
    - x86-64라면 long mode
    - ARM이라면 적절한 exception level / MMU 상태 등
- 메모리 초기화
	- 동적 메모리 할당(커널 이미지 위치 계산을 위한 간단한 vm, page table구현)
	- 최소한의 스택
	- BSS가 초기화
	- early page table: MMU 활성화 후, 주소 변환을 위해서 반드시 필요하다
- 커널 커맨드라인 전달
- initrd/initramfs 위치 정보 전달(커널 초기화 중 마운트 필요)
- 메모리 맵 정보
    - x86: e820/EFI memory map 계열
    - ARM: device tree 중심

부트로더 및 부트스트랩은 위 조건을 만족시키는 것이 목표다.
