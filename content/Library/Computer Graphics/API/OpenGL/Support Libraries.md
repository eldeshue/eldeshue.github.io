# GLFW
window를 생성하고 사용자 입력을 관리하며, OpenGL의 context를 생성하는 OpenGL 특화 라이브러리.

즉 OpenGL을 사용하기 위해서 필요한 기반 환경을 제공하는 라이브러리이다. 필수적인 기능만 제공하기에 대규모 프로젝트에는 적합하지 않다.

# GLAD
OpenGL 함수의 실제 구현은 GPU 제조사에서 제공하는 드라이버에 의해 이루어지며, 이 드라이버는 다양한 버전과 확장 기능을 포함하기 때문에 함수들의 정확한 메모리 주소(주소 값)는 구현마다 다르다. 또한 이 드라이버는 동적 라이브러리의 형태로 적재되어 실행되므로, OpenGL의 실재 구현은 컴파일 타임에 결정될 수 없다.

이 때 필요한 요소가 바로 GLAD(openGL loADer) 라이브러리다. GLAD 라이브러리는 런타임 시에 운영체제에서 제공하는 wglGetProcAddress(Windows), glXGetProcAddress(Linux) 등의 시스템 콜을 호출하여, 드라이버가 제공하는 각 함수의 주소를 조회하고, 그 결과를 저장한다. 이후, 이 로더 라이브러리가 드라이버의 구현과 응용프로그램이 호출한 OpenGl api 사이에서 mapping을 수행한다.

즉 GLAD와 같은 런타임 로더가 없다면, OpenGL은 실행이 불가능하다.

## DirectX의 경우
DX의 경우, COM 객체로 하드웨어를 추상화 한다. 그래픽 카드에 대한 COM 객체를 초기화 하는 과정에서 windows 운영체제는 그래픽 드라이버를 순회하여 실재 구현에 해당하는 함수의 주소를 COM 객체 내부의 함수 테이블에 초기화한다. 

따라서 GLAD와 같은 라이브러리는 필요하지 않지만, DX도 런타임에 api의 구현체를 결정한다.
