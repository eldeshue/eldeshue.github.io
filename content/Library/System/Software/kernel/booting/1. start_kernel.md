# Overview
start_kernel은 리눅스 커널의 부팅 과정 중, cpu와 memory, scheduler 초기화를 통해서 코어 커널 모듈 초기화를 수행하는 함수이다.

> start_kernel은 모든 arch에서 공통으로 호출됨
# Contents
## Context
- start_kernel 이전이 보장하는 것: 최소한의 c 코드 실행 환경
    - 스택, BSS, 코드(커널 이미지), 최소한의 paging 메모리, 부트 패러미터
- start_kernel 이후에 보장하는 것: 커널 코어 서브시스템
    - kernel의 init 프로세스 생성 가능, kernel 스레드 생성 가능, fs 및 드라이버 초기화 가능

## Implementation
### 0. 기타 기능 초기화
호출 직후에는 stack canary를 비롯한 보안 기능이나 cgroup 혹은 디버그 기능을 활성화 한다.
### 1. setup_arch
아키텍쳐 의존적인 초기화를 수행한다.

- setup_arch 이전이 보장하는 것: 최소한의 스택 및 메모리 정보, 기초 모드의 단일 booting cpu
- setup_arch 이후에 보장하는 것: 
    - 적절한 arch로 활성화 된 부팅 cpu
    - 하드웨어 가속이 활성화된 메모리(기초적인 할당자, 메모리 맵, 페이징, 등)

> 부트로더의 정보에 기반한 개선된 하드웨어(프로세서 + 메모리) 초기화

아키텍쳐에 따라서 구현이 크게 달라지지만, 대체적으로 다음의 내용을 수행한다.

- [[arm32 - setup_processor | setup_processor]] : 프로세서 초기화, 커널이 해당 프로세서의 기능을 인식하게 되며, 커널 코드가 프로세서를 통제할 수 있게 된다.
