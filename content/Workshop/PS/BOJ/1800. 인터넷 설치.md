# Problem
- 주어진 그래프에 대해서 K+1번째 엣지의 비용을 최소로 하는 경로를 찾아라.
- [링크](https://www.acmicpc.net/problem/1800)
# Solution
## Algorithm
- [[Parametric Search]]
- 최단 경로 알고리즘(다익스트라)
## Approach
문제에서는 가중치가 있는 그래프가 주어질 때, 1번 노드에서 N번 노드에 이르는 경로들 중, 비용순으로 정렬했을 때, K+1번째 엣지의 비용이 최소가 되는 값을 찾는 것이다.

가장 나이브한 접근은 당연히 모든 조합의 경로를 찾고, 각 경로에 대해서 엣지를 정렬하며, 그 중 K+1번째 엣지의 비용이 최소가 되는 것을 찾는 것이다. 당연히 조합론적 폭발에 의해 불가능한 풀이라고 할 수 있다.

그렇다면 어떤 접근이 필요했을까? 핵심은 **문제의 재정의**에 있다. 주어진 조합론적 최적화 문제는 탐색 범위가 너무 넓어 일반적인 방식으로는 해결이 불가능하다. 따라서 우리는 관점을 완전히 바꿔야 한다.

이때 유효한 전략이 바로 **결정 문제(Decision Problem)** 로의 변환이다. '최적의 값 $x$를 찾아라'라는 문제를 '$x$라는 답이 조건을 만족하는가?'라는 참/거짓의 문제로 바꾸는 것이다. 만약 이 결정 문제의 결과가 **단조성**(예: $x$에서 성립하면 $x+1$에서도 성립함)을 띤다면, 우리는 **매개변수 탐색(Parametric Search)** 을 통해 방대한 탐색 범위를 로그 시간 복잡도로 줄여낼 수 있다.

이 문제도 **x보다 큰 비용의 엣지를 K개 이하로 선택해서 1과 N을 잇는 경로를 구성할 수 있느냐**로 바꾸는 것이다. 

이 결정문제에서 우리는 다익스트라 알고리즘을 사용하여 x보다 큰 엣지의 비용을 1로 했을 때의 최소 비용 경로를 O(E log V)로 찾을 수 있다.  
# Implementation

## Code

``` cpp
#include <iostream>
#include <vector>
#include <queue>
#include <algorithm>

int main() {
	std::ios::sync_with_stdio(false);
	std::cin.tie(nullptr);
	std::cout.tie(nullptr);

	int N, P, K;
	std::cin >> N >> P >> K;
	using Edge = std::pair<int, int>;
	std::vector<std::vector<Edge>> graph(N + 1);
	for (int i = 0; i < P; ++i) {
		int n1, n2, c;
		std::cin >> n1 >> n2 >> c;
		graph[n1].push_back({ n2, c });
		graph[n2].push_back({ n1, c });
	}

	// Dijkstra as a check
	std::vector<int> parents(N + 1, -1);
	std::vector<int> costs(N + 1, 1e9);
	using Stat = std::pair<int, int>;
	std::priority_queue<Stat, std::vector<Stat>, std::greater<Stat>> pq;
	auto dijkstra = [&](int x) -> bool {
		std::fill(parents.begin(), parents.end(), -1);
		std::fill(costs.begin(), costs.end(), 1e9);
		std::priority_queue<Stat, std::vector<Stat>, std::greater<Stat>> pq;
		parents[1] = 0;
		costs[1] = 0;
		pq.push({ 0, 1 });
		while (!pq.empty()) {
			//pop
			auto const [cur_cost, cur_node] = pq.top();
			pq.pop();

			// compare
			if (cur_cost > costs[cur_node])
				continue;

			// enumerate
			for (auto const [next_node, c] : graph[cur_node]) {
				// 비용 x를 초과하는 간선을 몇 개 사용했는가?
				int const next_cost = cur_cost + static_cast<int>(c > x);
				if (next_cost < costs[next_node]) {
					// update
					parents[next_node] = cur_node;
					costs[next_node] = next_cost;
					pq.push({ next_cost, next_node });
				}
			}
		}

		return (costs[N] <= K);
		};

	// parametric search, find lower-bound of result area
	int l = 0, r = 1000001;
	while (l < r) {
		int mid = (l + r) >> 1;
		if (dijkstra(mid)) {
			r = mid;
		}
		else {
			l = mid + 1;
		}
	}

	// based on dijkstra, get edges
	if (l == 1000001)
	{
		std::cout << -1;
	}
	else {
		std::cout << l;
	}
	return 0;
}
```

# Summary
- 오랜만에 parametric search를 접해서 그런지, 결국 답지를 봐버렸다.
- 매개변수 탐색이 핵심이었지만, 결정문제를 구성함에 있어서 다익스트라를 쓰는 것도 인상적이다.
- 기존의 엣지의 비용을 그대로 쓰는 대신, x보다 크면 1로 판정해서 갯수를 경로의 비용으로 삼는다는 발상이 굉장히 인상적이었다.
