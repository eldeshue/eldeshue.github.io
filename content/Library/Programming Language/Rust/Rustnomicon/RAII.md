# Overview
Rust에서 구현된 RAII패턴에 대하여 다룬다.

# Constructor
rust는 C++와 달리 생성자가 단 하나 존재한다.
``` rust
struct Foo {
    a: u8,
    b: u32,
    c: bool,
}

enum Bar {
    X(u32),
    Y(bool),
}

struct Unit;

let foo = Foo { a: 0, b: 1, c: false }; // 구조체, 모든 필드 반드시 초기화
let bar = Bar::X(0); // 열거형, 하나의 variant의 모든 필드를 반드시 초기화
let empty = Unit; // 구조체, 필드가 없음
```
타입을 쓰고, 중괄호에 모든 필드를 채우는 방법만이 유일한 생성자이다.

이 생성자와 함수의 구분은 언어 시스템의 생성자 종속 정도로 생각할 수 있다. C++는 여러 특별한 생성자가 존재하고, 이들이 언어의 문법에 깊게 종속되어, 여러 부분에서 **암시적으로 생성자가 호출된다**. 그러나, rust의 문법은 생성자에 의존하지 않으며, 그 결과 절대 암시적으로 호출되지 않는다.

> **러스트에서 모든 것은 명시적으로 처리된다.**

할당 또한 마찬가지다. C++에서 복사, move 등 여러 assign이 있던 것과 달리, rust의 assign은 모두 기존 데이터의 drop + byte copy이다. 다만, copy, clone을 제공하여 복사를 표현한다.

> **Clone은 사용자 정의 객체 복사로, 절대 암시적으로 호출되지 않는다.**
> **Copy는 byte copy이지만, 기존 데이터를 uninit하지 않음을 의미한다.**

흔히 쓰이는 `new`는 `Default`에서 제공될 수 있으며, 모든 경우 생성자가 아니라 하나의 함수에 불과하다. 다만, 내부적으로 생성하는 로직을 가질 뿐이다.
# Destructor
## Drop
Rust의 소멸자라 하면, scope 끝에서 자동으로 호출되는 drop 트레잇이 유일하다.
``` rust
fn drop(& mut self)
```
인자로 mutable self를 받는데, 이는 해당 객체가 소멸하기 전에 drop 이 호출됨을 의미한다. 구체적인 소멸 수행 과정은 다음과 같다.

> 객체의 소멸 -> drop 함수 실행 -> 각 필드에 대해서 소멸자 호출 -> 메모리 해제

또한 인자 self가 ref이므로, 필드의 move는 발생하지 않는다. 

이러한 Drop의 메커니즘이 특별하게 여겨지는 이유는 drop의 호출이 Rust답지 않게 암시적이기 때문이다. 어떤 타입에 Drop트레잇이 없더라도, 각 필드의 drop은 재귀적으로 호출될 수 있기 때문이다.

> **예외적으로 Drop의 동작은 암시적이다.**

사실 drop의 작동 방식 자체는 C++를 비롯한 여러 구현에서 동일하게 보이는 굉장히 일반적인 방식이다. 그러나 예외적으로, 이러한 구현에서 벗어나는 경우, 즉 **소멸 순서에 sensitive한 경우에는 고려할 필요가 있다.**
# Leak
소멸자가 호출되지 않는 경우를 누수(Leak)이라 흔히 부른다. 그렇다면, 이러한 누수는 unsafe한가? 충격적이게도 safe하다.

> **Leak은 safe하다.**

생각해보면, 자원의 누수는 바람직하지는 않지만, unsafe하지는 않다. 이론적으로 누수된 자원은 접근이 불가능할 뿐, 접근 자체는 여전히 합법적이다. 이러한 맥락에서 **객체의 소멸자를 호출하지 않고, 소유권을 소멸시키는 함수, mem::forget**이 존재하며, 이는 safe rust의 일부이다.
## Proxy Type
프록시 타입은 어떠한 자원에 대한 접근(ref)은 제공하지만, 소유는 하지 않는 타입을 말한다. 대표적으로 **Rc** 같은 컨테이너가 이에 해당한다.

이러한 proxy type을 구현할 때, forget의 결과에도 여전히 안전한 unsafe rust를 구사해야 한다. 그러나 이는 상당히 어려운 일인데, rustnomicon에서는 세 가지 예를 들어서 이들이 쉽지 않음을 보여준다.
