# Overview
렌더링 과정에 대한 기본적인 개념을 정리한다.
# Definition
렌더링이란 3D 공간에서 정의된 점(vertex)의 모음으로 존재하는 물체(object)를 평면(image)으로 만드는 행위이다.

렌더링은 피사체인 3차원 물체와 해당 물체를 바라보는 시점을 입력으로 받아서 해당 시점에서 바라본 2차원 이미지를 생성하는 과정이다.
## Input - 3D object
렌더링 과정은 3D 물체를 2D 이미지로 바꾸는 과정이다.

물체는 점의 집합으로, 이들 점이 어떻게 이어지는지(위상)에 대한 정보를 포함한다. 위상 정보는 렌더링 과정에서 실현된다.
### Topology
오브젝트를 구성하는 점들이 어떻게 연결되는지에 대한 정보, 흔히 3개의 점을 묶어서 평면을 구성하거나 2개의 점을 이어서 직선(와이어 프레임)을 만든다.

위상 정보는 index buffer의 형태로 저장하는데, 연결 관계에 있는 정점의 인덱스를 인접해서 배치한 형태다.

OpenGL에서 Topology는 [[Element Buffer Object]]로 관리된다.
## Input - Camera
3차원 물체는 해당 물체를 바라보는 시점에 따라서 그 이미지가 달라진다. 이러한 시점을 흔히 카메라라고 하며, 시점의 위치를 의미하는 하나의 점과 해당 위치에서 바라보는 방향을 정의하는 하나의 행렬(혹은 두 개의 벡터)로 정의된다.
## Output - 2D image
렌더링의 결과 얻어지는 데이터는 픽셀의 2차원 배열이다. 각 픽셀은 보통 4개의 float값으로 구성된다. 각각이 R,G,B,A이며, A는 투명도를 의미한다.

이 2D 이미지는 사람의 눈이 바라보는 위치에 따른 색을 의미하며, 이를 얻는 방법은 하나가 아니다.
## Procedure - Graphics Pipeline
입력으로 주어진 3D 물체와, 그 물체를 바라보는 시점을 입력으로 삼아 2D 이미지를 생성하는 과정을 그래픽스 파이프 라인, 혹은 렌더링-파이프라인 이라 부른다. 
### Shader
이러한 그래픽스 파이프라인은 순차성이 강제되는(즉, 이전 과정의 결과물을 입력으로 필요로 하는) 경우를 제외한 많은 부분이 서로 독립적이라, 병렬 수행에 매우 적합하다. 이러한 병렬성에 크게 최적화된 프로세서가 바로 gpu로, 간단한 ISA를 가지는 작은 코어를 매우 많이 가지고 있어 각각의 코어에 독립적으로 프로그램을 실행하여 이득을 본다.  이 때, 각각의 코어에서 실행되는 gpu 전용 프로그램을 바로 shader라 한다.

이들 shader는 실행 시간에 compile 되고 적재되어 각 데이터를 가공한다. 이 때 가공하는 데이터의 종류에 따라서 vertex shader, pixel shader, compute shader, 등 다양한 이름으로 불린다.

렌더링은 결국 여러 셰이더를 어떤 순서로, 어떻게 적용하는 지에 대한 것이다.

### 1. Vertex Shader
정점 셰이더. 입력으로 정점을 받아서, 모종의 연산을 거친 후, 새로운 정점을 반환한다. 일반적으로는 3D 물체를 구성하는 정점에 대하여 global matrix 혹은 view matrix를 적용하여 행렬 변환을 수행, 변환된 좌표계의 정점을 얻는 용도로 사용한다. 

vertex shader를 거친 정점 데이터는 모두 NDC로 조정되어야 함. 절댓값 1을 벗어나는 데이터는 clipping될 것임.

NDC 좌표계는 screen 좌표계(또는 viewport 좌표계)와 다르다. 따라서 스크린 좌표계로의 변환이 필요하다.
### 2. Geometry Shader
기하 셰이더. 입력으로 정점들을 받아서, 새로운 정점들을 생성한다. 3D 물체는 정점의 모임이므로, 입력으로 받은 물체를 바탕으로 하여 새로운 물체를 생성한다고 볼 수 있다.

런타임에 정점을 생성하는 것이므로, 예상컨데 물체의 파괴로 인한 파편의 생성 등에 쓰일 수 있지 않을까 추측한다.

기하 셰이더의 적용 여부는 선택적이다. 따라서, 불필요하다면 생략하는 것이 맞다.

### 3. Primitive Assembly
앞서 여러 셰이더를 통과한 일련의 정점들은 미리 정의된 topology에 따라 primitive로 결합된다. 

primitive(원시적인)라 부르는 이유는 복잡한 3D 물체를 구성하는 원시적인 구조(점, 선, 삼각형, 등)를 의미하기 때문이다. 

이 단계를 거치는 이유는 gpu가 이러한 원시적인 구조만 그릴 줄 알기 때문이다. 따라서 우리는 복잡한 대상을 그리기 위해서  정점들을 primitive로 한 번 결합하고, 이 primitive들을 다시 결합한다.

이러한 primitive의 대표가 바로 polygon으로, polygon은 primitive 중 삼각형이다. 

### 4. Rasterization
래스터화 단계. 이 단계는 앞서 구한 primitive들을 출력할 평면의 pixel과 매핑하는 과정이다. 매핑 과정에서 각 픽셀의 색이 결정되고, display 될 평면에 걸치는 primitive는 clipping(절단)한다. 

입력으로는 이전 과정에서 생성된 primitive를 받으며, 그 결과로 fragment를 생성한다. 

fragment는 픽셀의 후보가 되는 데이터로, 후보인 이유는 여러가지 이유(clipping, 색 혼합, 다른 fragment에 의해서 가려짐, 등) 이유로 폐기될 수 있기 때문이다. 

### 5. Fragment Shader
이 단계는 각 fragment의 색을 결정하는 과정이다. 광원에 의한 효과나 그림자 등이 여기서 적용된다. 복잡한 계산이 도입되는 부분으로, 그래픽스 api가 제공하는 고급 기능들이 대부분 여기서 작용한다. 
### 6. Creating Image
지금까지의 과정을 거친 fragment들은 픽셀의 후보에 불과하다. 여러 과정을 추가적으로 거쳐야 비로소 pixel이 되고, image를 획득할 수 있게 된다. 다음은 최종적으로 이미지를 획득하기 위해서 거치는 단계들이다.
#### Alpha Test and Blending
각 fragment들은 RGB값에 더해서 A값을 갖는데, 이 A값은 투명도를 의미한다. 따라서 어떤 물체의 A값에 따라서는 해당 물체 뒤의 대상이 투과되어 보일 것이다. 투과를 구현하기 위해서는 색을 섞어야 하는데, 이 과정을 혼합(blending)이라 한다. 

이러한 투과는 성당의 스탠드 글래스를 생각하면 편하다. 스탠드 글래스는 보통 색이 있는 유리이며, 유리이기에 뒤의 물체를 투과해서 보여주지만, 동시에 스탠드 글래스의 색이 함께 작용한다.
#### Curling
컬링은 어느 한 물체에 의한 가려짐을 의미하며, 투과가 발생하지 않는다면, 카메라를 기준으로, 앞의 물체는 뒤의 물체를 완전히 가릴 것이다. 이 경우 가려진 fragment는 버려지고, 가린 fragment만을 취하게 된다. 

가려짐의 기준이 되는 값은 카메라로부터의 거리인데, 이를 반드시 관리해야 한다. 

curling을 위해서는 fragment를 depth에 따라서 정렬할 필요가 있는데, 이는 상당히 비싼 연산이며, z buffering이라는 하드웨어 가속을 받아서 해결한다.
