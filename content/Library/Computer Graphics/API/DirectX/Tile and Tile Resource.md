# Overview
사용자(응용프로그램)로 하여금 **GPU의 virtual memory를 수동으로 관리할 수 있게** 하는 타일과 그 타일에 적재해서 사용하는 타일 리소스에 대해서 알아보자.
# What is Tile?
MSDN에 의하면 타일의 정의는 다음과 같다.
>메모리의 CPU/시스템 페이지와 비슷한 비디오 메모리의 페이지입니다. 타일 표기법은 GPU 가상 메모리 하위 시스템과 CPU 가상 메모리 하위 시스템을 구분하는 데 도움이 됩니다. GPU는 시스템 가상 메모리와 비슷한 가상 메모리 기능을 제공합니다. 일부 GPU는 가상 메모리 기능을 공유하여 CPU와 GPU 모두에서 가상 메모리 하위 시스템의 일부 페이지를 공유할 수 있습니다.

즉, 타일은 **GPU의 vram에 대한 page**이다. 

타일은 타일 풀(tile pool)에서 관리되면, 필요에 따라 tile pool에서 타일을 얻은 다음, 이를 실제 물리적 메모리와 mapping해서 사용함. mapping되지 않은 tile은 UB을 발생시킴.

실제 타일이 매핑되는 공간은 buffer의 종류에 따라 달라짐. default는 gpu, read back은 cpu...
# What is Tile Resource?
> **크고 복잡한 리소스를 작은 메모리 블록(타일) 단위로 나누어 GPU 메모리에 동적으로 매핑(mapping)하는 기능**.

어떤 큰 자원(초대형 텍스쳐 등)을 전체 다 vram에 load하는게 아니라, tile과 매핑하여, 필요한 순간에만 load하는 등, virtual memory의 형태를 빌리는 기술.

실제 존재하는 자원을 가상의 메모리, 타일에 매핑하고, gpu에게는 타일 단위로 읽도록 할 수 있음.

MSDN의 보다 자세한 설명에 의하면 타일 리소스의 정의는 다음과 같다.
> 애플리케이션에서 액세스할 수 없는 것으로 알려진 화면 영역을 저장하는 데 소모되는 GPU 메모리를 줄이고 하드웨어에서 인접한 타일에서 필터링하는 방법을 이해할 수 있도록 하려면 타일식 리소스가 필요합니다. 타일식 리소스는 논리적 큰 리소스이지만 적은 양의 실제 메모리를 요구합니다.
- 타일은 vram의 페이지, 따라서 cpu는 접근할 수 없음.
- 매핑된 구조이고, 실제로는 vram에 자원이 존재하지 않음(필요하면 생김). 따라서 실제 요구 메모리는 매우 작음.

# 왜 굳이 Tile Resource를 사용하는가?
우리는 이미 GPU가 virtual memory를 운영함을 알고 있다. 즉 default heap도 virtual memory로 관리될텐데, 왜 tile이 필요해지나?
- 메모리 유틸리티 : 앞서 설명한 vram 낭비 방지
- 보다 섬세한 vram 사용 최적화
- GPU page fault를 예측하고 방지 가능
# Summary

| 비교 항목      | Default heap       | Tile Resource                |
| ---------- | ------------------ | ---------------------------- |
| 가상 메모리     | **드라이버/OS가 자동 관리** | **앱이 직접 관리 (타일 단위 매핑)**      |
| 메모리 로딩 시점  | 필요 시 자동 페이징 또는 로딩  | 앱이 필요한 시점에 수동 로딩             |
| 메모리 크기     | 전체 VRAM에 로딩 가능성 있음 | 실제로 사용하는 타일만 로딩 가능           |
| LOD / 스트리밍 | 기본 기능만 제공          | **사용자 제어 가능 (LOD, 스트리밍 타일)** |
| 사용 난이도     | 쉬움                 | **복잡하지만 유연함**                |
| 커스텀 메모리 정책 | ❌ 제한적              | ✅ 가능 (메모리 압박 대응 등)           |
tile과 tile resource는 vram을 보다 효율적으로 사용하기 위한 기술이다. 다만, 특별한 목적이 아니면, 그다지 사용할 일은 없다고 생각된다.
