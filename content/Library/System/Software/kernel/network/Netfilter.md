# Overview
리눅스의 방화벽(패킷 필터링)에 대해서 정리한다.
# Contents
## 5-tuple
리눅스 커널의 표준 네트워크 스택은 L4까지 구현된다. 그렇기에 모든 패킷은 최종적으로 L3, L4 정보를 종합하여 패킷을 구분하며 그 구성은 다음과 같다.
- source ip
- destination ip
- source port
- destisation port
- protocol id
IP에 기반한 모든 패킷은 위 5가지 필드의 조합으로 구분되며, 이를 묶어서 5-tuple이라 부른다.
## action
5-tuple이 패킷을 구분하기 위한 식별자라면, action은 방화벽이 이 패킷에 대해서 어떤 동작을 수행할 지에 대한 내용이다.

모든 패킷은 어느 순간에 5-tuple을 완성하게 되고, 이 패킷은 방화벽 정책과 매칭을 시도, 성공하면 정책이 정의하는 동작을 수행하는데, 이 동작이 곧 action이다.

action에는 다음의 세 가지가 존재한다.
- accept: 내가 목적지이므로, 받아들여서 위로 올린다.
- forward: 내가 최종 목적지는 아니지만, 학습된 neighboring에 의해 알려진 네트워크 내부의 다른 노드로 전달한다.
- drop: 패킷을 삼킨다. 나를 도착지로 삼지 않으면서 forward도 하지 않는 경우 주로 발동한다. 

> **5-tuple과 action이 결합되어 하나의 규칙(Rule)을 구성한다.**
## Implementation
5-tuple과 그에 대한 matching을 어떻게 찾느냐에 따라서 다음의 구현체들이 존재한다.

이하는 모두 소프트웨어적 구현체이지만, 일부 고성능 장비에서는 하드웨어적 솔루션이 개발되었다. TLB와 유사한 하드웨어 구현된 해시테이블을 이용한 것으로 TCAM이라 한다.
### Iptables - linear search
테이블을 선형으로 탐색, 매칭된 action을 수행한다.

복잡도는 O(N)이며, 적은 수의 정책에서는 문제가 없지만, 큰 트래픽이 몰리거나 복잡한 설정으로 인해서 테이블이 커지는 경우 문제가 된다.

현재 잘 쓰이지 않는다.
### nf-hiPAC - tree search
netfilter - high performance packet classification, 성능이 나쁜 iptable을 개선한 구현체.

단순 테이블 순회가 아닌, 기하학에 기반한 다차원 트리로 구현, 5-tuple의 탐색을 검색 트리에 기반하여 수행한다.

트리가 자동 균형을 수행하며, depth가 매우 엄격하게 괸리된다. 시간 복잡도는 O(log N).

장점은 이론 상으로 효율성인데, 트리의 depth를 매우 엄격하게 관리하기 때문이며, 대용량 처리가 필요한 경우 유의미하다.

문제는 단점이다. 일단 알고리즘 자체가 매우 고급이라 개선이 어렵고, 구현 자체가 트리에 강하게 결합되어서 확장도 쉽지 않다. 따라서 확장성이 매우 떨어지는 구조다.

또한 설정된 정책의 수가 늘어날수록 트리의 크기가 폭발적으로 증가하는 기하학적 폭발 문제가 존재한다.

> **리눅스 커널 표준이 아닌 관계로, 더 이상 개발 및 유지보수되지 않는다.**
### nftables - hash map + optimized search tree

커널 내부에 패킷 필터링을 그 자체를 수행하는 엔진 역할의 가상머신(Netfilter VM)을 두고, 이 가상머신에 사용자의 정책을 바이트코드로 주입, 필터링을 수행한다. 이 때 정책을 바이트코드로 복사 및 컴파일하는 과정이 필요하다.

nftables는 기본적으로 고성능 자가균형트리에 그 구현을 의존한다. 따라서 기본적으로 O(log N)인데, 여기에 추가로 hash map을 활용하여 ip + port + protocol의 세 필드를 하나의 key로 조합하여 hash table에 look-up하도록 한다.

이러한 자료구조는 정책을 컴파일하는 과정에서 빌드되며, 가상머신은 이를 정적으로 참조한다.

가상머신에 의한 정책 구조의 압도적인 범용성과 훌륭한 평균 성능을 장점으로 한다.

>  **현대 리눅스 커널 표준 넷필터 구현.**
### 모던 - nftables + DPDK & eBPF 
현대 리눅스 커널은 nftables에 여러 스택 우회기술을 조합한 하이브리드 방식으로 진화를 꾀한다.

표준 패킷 경로는 nftables이지만, 각자 여러 기술을 도입한 여러 우회로를 준비하는 방식이다. 이러한 우회로를 구성하는 기술이 바로 DPDK 및 eBPF이다.

이들은 모두 네트워크 스택의 특정 지점의 데이터를 빼내어 user-space에서 가공하는 방법으로 추후 별도의 연구가 필요하다.
