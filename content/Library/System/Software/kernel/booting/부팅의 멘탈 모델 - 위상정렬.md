# Overview
커널의 각 서브시스템을 노드, 이 노드 사이의 의존관계를 그래프로 모델링하였을 때, 부팅 과정을 과연 어떻게 바라봐야 하는가?

부팅은 곧 **위상정렬**이다.
# Contents
## 부팅의 문제 - 순환참조

![width:800px](kernel_subsystem_cycle.png)

- A를 하려면 B가 필요한데, B를 하려면 A가 필요함 -> **순환참조**
## Solution - Vertex Split

![width:1000px](booting_by_intermediate_system.png)
- 모든 기능이 필요한 것이 아님, 일부로 충분
- **현재 가용한 기능**으로 구성할 수 있는 마이너 카피 구현
- 가능한 초기화 수행 후, 다음 노드(**개선된 실행 환경**)로 이동
- 응용 프로그램 실행 가능한 환경까지 이를 반복

> bootstrap 실행을 위한 임시 stack

> earlyxxx (earlycon, earlyprintk, ...)
# Summary
- 커널은 기능을 노드로 삼는 그래프로 모델링
- 부팅은 이 그래프의 의존 관계를 존중하는 노드 순회, **위상정렬**
- 위상정렬을 위해 사이클의 해소가 필요
- 이를 위해 임시 실행 환경을 만들고, 이를 확장하며 진행한다

---

부팅과정에서 진정으로 중요한 것은 각각의 구현이 아님(본인이 BSP가 아니라면...). 오히려 어떤 단계에 어떤 동작이 가능한지, **커널 코드가 기대하는 계약**이 중요함.

- 전후 맥락, context가 중요하다
    - 이 코드의 수행을 위해서는 어떤 기능이 필요한가?
    - 현재 코드는 무엇을 활성화 했는가?
    - 이 코드로 인해 활성화 된 기능이 어디에 영향을 미치나?
